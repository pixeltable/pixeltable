# Establish the job

Keep one person or role and one job. Read the product or proposal before filling the card:

- Person or caller, and whether stated or inferred.
- Situation and desired result.
- Done: the observable result that establishes completion.
- Leave: the condition that prevents or ends the attempt.
- Path: the actual screens, commands, pages, or calls.
- Evidence: observed execution, source, proposal, or open question, with locations.

The door depends on the job. A CLI starts with help and the first useful command. A library or API starts with installation and one working example. Documentation succeeds when its example works. A landing page may end in a decision rather than an application action.

Use an existing card in the conversation or established artifact location. Keep its person, job, done, and leave for a follow-up. Read the product again and update paths that moved. Do not silently substitute a different person or job.

Run a local product or example when available and authorized. If access requires an unavailable account, key, deployment, or tool, inspect source where possible and label the result. Do not invent live observations or feelings. A proposed scenario is not user research.

Keep one-off notes in the response. If the user requests persistent artifacts, use their chosen location, or `lifecycle/job.md` by default. Preserve existing artifacts unless replacing them is authorized.
