# Stages

Read the sections for the stages in this reach. For a full session, read all of them.

## The door

Set the arrival kind on the job card before the path. The door is the first thing they do.

- **Finish a job.** An app, a CLI, a dashboard, a plugin. Done is the job, finished. The door is the first action that starts that job. For a CLI, that action is the help text and the first command that does the job.
- **Decide.** A landing page, a pricing page, a campaign. Done is a choice they can name. The door is that choice.
- **Understand.** Docs, a tutorial, a notebook, a help page. Done is they can do the thing the page described, on the real product. The door is the first command or the first example on the page.
- **Make one call work.** A library or an API. Done is one call that returns. The door is the install line and the smallest example.

Walk the door this product has. Docs are done when they have run the example and can point at the result. A landing page is done when they have made the choice, or left. A CLI is done when the command has printed the result of the job.

## Arrival

Find the first sentence they can read before an account, an install, or a command.

They need to tell what this is, and that it matches the job on the card.

Write the door they actually use, in the product's words.

If the first sentence describes the product and never the job, that is the finding. Quote the sentence.

## Entry

The first screen, prompt, or file after they go through the door.

Write what is already filled in. Write the single action that begins the job.

If several actions sit in front of that one, name them. Say whether anything marks the one that starts the job.

## First success

The smallest end of the job. Leave the rest of the product for a later visit.

Quote the confirmation. If the product stays silent after a correct action, that silence is the finding.

Write whether the next action is on that same screen. If the job is finished, quote what the screen offers next.

## The same job again

They do the job a second time, with whatever the first time left behind.

Write what they have to enter again. Write what the product kept.

If the second time takes the same steps as the first, say so. For a job they will repeat, that equal length is the finding.

## Trouble

Pick two the product can produce. Produce them. Quote what comes back.

- **Empty.** Nothing here yet: a first visit, an empty list, a missing file. Quote the empty state. If there is no empty state, the gap is the finding.
- **Wrong.** A value the product refuses, or a command that fails. Use a mistake this person would make on this job, and quote the refusal.
- **Wait.** The product is working, and they have no way to tell. A spinner with no words, a command that prints nothing until the end.
- **Closed.** Permission, a missing key, a paywall, a disabled control. Quote the reason the product gives. If it gives none, the gap is the finding.
- **Return.** They stop and come back the next day, or after the file closes. Write what is still there, and what they have to rebuild.
- **Undo.** They did the thing, and it was the wrong thing. Write whether the product can take it back, and quote the words it uses.

Name the troubles you looked for and could not produce, and what you tried.

## Leaving

They stop on purpose.

Write whether they can tell the work is kept, where it is, and how to take it with them. Quote those words.

If closing the product drops the work, and the product never says so, that is the finding.
