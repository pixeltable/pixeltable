# The job card

The file is `lifecycle/job.md` in the product's project. Commands share it so the person and the job stay put.

Write it in this shape:

```markdown
# Job

- Person:
- Situation:
- Arrival kind:
- Job:
- Done:
- Leave:
- Path:
- Stages this product does not have:
- Source:
```

- **Person.** One name, taken from the person the product speaks to. If the product names no one, write that, and use the narrowest person the first screen implies.
- **Situation.** What they are in the middle of.
- **Arrival kind.** Finish a job, decide, understand, or make one call work. [stages.md](stages.md) says what the door is for each kind.
- **Job.** The thing they came to finish.
- **Done.** What they can point at when it worked.
- **Leave.** What would make them stop.
- **Path.** The screens, commands, or pages in the order they meet them, each named from what you read.
- **Stages this product does not have.**
- **Source.** Watched, or read from source. Name the file or the screen.

Read the product before you fill a line. Use it the way they would, when you can.

- A page or a server that is already running: open it and quote the words on the screen.
- A CLI: run the help and the job, and quote the output.
- A library or an API: run the first example, and quote what comes back.
- The README's first command starts the product with no account and no key: run it, then use it.
- It needs an account, a key, or a deploy: read the source, and say the session was read from source.

If the file already exists, keep the person, the job, done, and leave. Read the product again. Update the path when it moved, and say what moved. A new person is a new card: ask before you replace the file.
