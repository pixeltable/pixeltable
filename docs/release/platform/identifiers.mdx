title: 'Identifiers and Naming'
description: 'Naming rules for directories, tables, columns, and indexes'
---

Every name in the Pixeltable catalog -- directories, tables, columns, indexes, and the database itself -- is an
**identifier**. Identifiers are case-insensitive: Pixeltable folds them to lower case on the way in, then stores and
displays the folded form.

## Case-insensitivity

```python
pxt.create_dir('MyDir')
t = pxt.create_table('MyDir.MyTable', {'MyCol': pxt.Int})

# every spelling reaches the same table and the same column
pxt.get_table('mydir.mytable')
t.MyCol, t.mycol, t['MYCOL']

# the stored and displayed name is the folded one
t.columns()                      # ['mycol']
t.select(t.MyCol).collect()      # result key: 'mycol'
```

Select aliases and imported column headers fold as well:

```python
t.select(Total=t.MyCol + 1).collect()   # result key: 'total'
pxt.io.import_pandas('films', df)       # DataFrame column 'FilmName' becomes 'filmname'
```

Because folding happens on the way in, two spellings of one name cannot coexist:

```python
pxt.create_table('films', {'title': pxt.String, 'Title': pxt.String})
# Error: Column names are case-insensitive, but 'title', 'Title' were specified
```

The same check guards insert and update specs, iterator output schemas, and the fields of a Pydantic model passed
to [`to_pydantic()`](/sdk/latest/query).

## Character rules

| Kind | Rules |
| ---- | ----- |
| Column, index | unaccented letters `a`-`z`, digits, and `_`; may not begin with a digit or with `_` |
| Directory, table, database | the same, plus `-` anywhere but the first character |

Accented letters and other scripts are not allowed. Plain letters lower-case identically in Python and in the
store, so a name means the same thing no matter which layer folds it.

## Reserved names

A column name may not be a Python keyword, nor the name of a `Table` method (`count`, `insert`, `select`, ...), so
that attribute access such as `t.my_col` stays unambiguous. Folding applies first, so `Count` and `Class` are
rejected just as `count` and `class` are. Index names follow the column rules.

`pos` is reserved for the position column of a component view, so an iterator cannot name an output `pos`.

## What is not an identifier

Data is never folded. JSON path components are dictionary keys, so they stay case-sensitive:

```python
t.event.someField   # a different key from t.event.somefield
```

String values, file paths, and URLs are likewise untouched.

## Database names

`PIXELTABLE_DB` names the Postgres database that holds the catalog. It follows the directory and table rules, and is
limited to 63 characters, the length Postgres accepts. If you configured a mixed-case name before Pixeltable started
folding, Pixeltable keeps using that existing database and warns you.
