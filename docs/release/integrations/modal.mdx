---
title: 'Modal'
description: 'Run built-in Pixeltable UDFs on Modal CPU and GPU containers'
---

Each built-in UDF you list under `[tool.pixeltable.udf]` in `pyproject.toml`, or `[pixeltable.udf]` in `pixeltable.toml`, runs on its own Modal Server, with the CPU, memory and GPU you give it. Tables, indexes and the other columns stay in your local database or your hosted database; only the calls to the listed UDFs go to Modal.

`pxt db update` builds the container image from your project's `uv.lock` in Pixeltable Cloud and deploys the servers. You sign in with `pxt login`; you need no Modal account or token.

<Note>
  Only synchronous UDFs under `pixeltable.functions` can be listed. `pxt` refuses the setting if it names a `@pxt.udf` of your own or an async UDF.
</Note>

## Configure UDF servers

Add one section per UDF. When a listed UDF processes video or audio, add a `[[tool.pixeltable.database]]` entry named `local` with `system_dependencies = ['ffmpeg']`, which installs FFmpeg in the image.

```toml pyproject.toml
[project]
name = "modal-demo"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = ["pixeltable[serve]", "torch>=2.11", "transformers>=5.6", "timm>=1.0.11"]

[tool.pixeltable]
log_level = "DEBUG"

[tool.pixeltable.udf.'pixeltable.functions.video.clip']
cpu = 2

[tool.pixeltable.udf.'pixeltable.functions.video.segment_video']
cpu = 2

[tool.pixeltable.udf.'pixeltable.functions.video.concat_videos']
cpu = 2

[tool.pixeltable.udf.'pixeltable.functions.image.rotate']
cpu = 1

[tool.pixeltable.udf.'pixeltable.functions.huggingface.clip']
cpu = 2
memory_mb = 4096
gpu = "T4"

[tool.pixeltable.udf.'pixeltable.functions.huggingface.image_captioning']
cpu = 2
memory_mb = 8192
gpu = "T4"

[tool.pixeltable.udf.'pixeltable.functions.huggingface.detr_for_object_detection']
cpu = 2
memory_mb = 8192
gpu = "T4"

[[tool.pixeltable.database]]
name = 'local'
system_dependencies = ['ffmpeg']
```

In `pixeltable.toml`, drop the `tool.` prefix: `[pixeltable.udf.'pixeltable.functions.video.clip']`, `[[pixeltable.database]]`.

| Field | Type | Default | Effect |
| --- | --- | --- | --- |
| `cpu` | `float` | Modal's | vCPUs per container |
| `memory_mb` | `int` | Modal's | Memory per container, in MB |
| `gpu` | `str` | none | Modal GPU spec, such as `'T4'`, `'L4'` or `'H100:2'` |
| `max_containers` | `int` | `2` | Containers the server runs at most |
| `timeout_seconds` | `int` | `300` | How long a call waits for its response, including time queued behind busy containers (`1` to `300`) |

Set `pixeltable.udf` only in the project configuration file. Pixeltable ignores `PIXELTABLE_UDF` with a warning, and refuses the setting as a `pxt.init()` override or in `~/.pixeltable/config.toml`.

## Write the application file

In this `app.py`, `bboxes_draw()` runs locally on the output of DETR; every other computed column and the embedding index call a UDF listed above.

```python app.py
import pixeltable as pxt
from pixeltable.functions import huggingface, vision
from pixeltable.functions.video import concat_videos, frame_iterator
from pixeltable.serving import FastAPIRouter

TableModel = pxt.model_base()

CLIP_MODEL = 'openai/clip-vit-base-patch32'
CAPTION_MODEL = 'Salesforce/blip-image-captioning-base'
DETECTION_MODEL = 'facebook/detr-resnet-50'


class Videos(TableModel, name='videos'):
    video_id = pxt.Column(type=pxt.Int, primary_key=True)
    video: pxt.Video
    excerpt = video.clip(start_time=0.0, duration=2.0)
    segments = video.segment_video(duration=5.0)


class Frames(TableModel, name='frames', base=Videos, iterator=frame_iterator(video=Videos.video, fps=1)):
    rotated = frame.rotate(90)
    caption = huggingface.image_captioning(frame, model_id=CAPTION_MODEL, model_kwargs={'max_length': 30})
    detections = huggingface.detr_for_object_detection(frame, model_id=DETECTION_MODEL, threshold=0.8)
    annotated = vision.bboxes_draw(frame, detections.boxes, labels=detections.label_text, width=3)
    __indexes__ = [pxt.EmbeddingIndex(frame, embedding=huggingface.clip.using(model_id=CLIP_MODEL), name='frame_ix')]


@pxt.query
def frames(video_id: int) -> pxt.Query:
    return (
        Frames.where(Frames.video_id == video_id)
        .order_by(Frames.pos)
        .select(Frames.pos, Frames.rotated, Frames.caption, Frames.detections, Frames.annotated)
    )


@pxt.query
def similar_frames(text: str, limit: int = 3) -> pxt.Query:
    sim = Frames.frame.similarity(string=text)
    return (
        Frames.order_by(sim, asc=False)
        .limit(limit)
        .select(Frames.video_id, Frames.pos, Frames.caption, Frames.annotated, sim=sim)
    )


@pxt.query
def with_excerpt(video_id: int) -> pxt.Query:
    return Videos.where(Videos.video_id == video_id).select(joined=concat_videos([Videos.video, Videos.excerpt]))


demo = FastAPIRouter(name='demo')
demo.add_insert_route(
    Videos,
    path='/videos',
    inputs=[Videos.video_id],
    uploadfile_inputs=['video'],
    outputs=[Videos.video_id, Videos.excerpt, Videos.segments],
)
demo.add_query_route(path='/frames', query=frames)
demo.add_query_route(path='/similar', query=similar_frames)
demo.add_query_route(path='/with-excerpt', query=with_excerpt)
```

## Deploy and run

<Steps>
  <Step title="Install dependencies">
    `uv sync` writes `uv.lock`, from which Pixeltable Cloud builds the image. The local process uses `torch` and `transformers` to embed the text of a `/similar` query.

    ```bash
    uv sync
    source .venv/bin/activate
    ```
  </Step>
  <Step title="Deploy the UDF servers">
    Without a database URI, `pxt db update` deploys the servers of your local database. For a hosted database, pass its URI: `pxt db update pxt://org:db`.

    ```bash
    pxt login
    pxt db update
    pxt db status
    ```
  </Step>
  <Step title="Create the tables and start the service">
    ```bash
    pxt schema update app.py demo
    pxt service update app.py demo -f
    URL=$(pxt service list demo --json | jq -r '.[] | select(.name == "demo") | .endpoint')
    ```
  </Step>
  <Step title="Insert a video and query it">
    The first insert starts the containers and downloads the Hugging Face weights. A container stops after 60 seconds without calls.

    ```bash
    curl -F video_id=1 -F video=@sample.mp4 "$URL/videos"
    curl -H 'Content-Type: application/json' -d '{"video_id": 1}' "$URL/frames"
    curl -H 'Content-Type: application/json' -d '{"text": "busy street with traffic"}' "$URL/similar"
    curl -H 'Content-Type: application/json' -d '{"video_id": 1}' "$URL/with-excerpt"
    ```
  </Step>
</Steps>

## Change UDF settings and secrets

After you change `[tool.pixeltable.udf]`, a Python file of the project or `uv.lock`, run:

```bash
pxt db update
pxt service update app.py demo -f
```

Until `pxt db update` finishes, a query fails with an error that the UDF servers run another version of the project.

A listed UDF that reads a provider key, such as `OPENAI_API_KEY` or `HF_TOKEN`, gets it from Pixeltable Cloud:

```bash
pxt secret set pxt://org OPENAI_API_KEY=sk-...
pxt db update
```

`pxt db update` refuses a project configuration file that holds a secret (`api_key`, `api_secret`, `api_token`, `token`, `storage_account_key` or `exporter_otlp_headers`). See [Configuration](/platform/configuration#per-database-settings).

## Inspect calls and clean up

With `log_level = "DEBUG"`, the service logs one line per call: the UDF, the row count, the round-trip time, the time inside the UDF and the Modal container:

```bash
grep 'Modal call of' "${PIXELTABLE_HOME:-$HOME/.pixeltable}"/logs/*.log
```

`pxt db delete` deletes the UDF servers and keeps your local tables:

```bash
pxt service stop demo
pxt db delete
pxt daemon stop
```

An idle UDF server runs no containers. Pixeltable Cloud deletes the UDF servers of a local database unused for 30 days.
