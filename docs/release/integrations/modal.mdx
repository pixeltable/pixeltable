---
title: 'Modal'
description: 'Run built-in Pixeltable UDFs on Modal CPU and GPU containers'
---

Pixeltable runs built-in synchronous UDFs listed under `[pixeltable.udf]` in `pixeltable.toml`, or `[tool.pixeltable.udf]` in `pyproject.toml`, on dedicated Modal Server containers over HTTP/2. Your tables, indexes, and unlisted columns stay in your local database or your hosted Pixeltable Cloud database, and only calls to the listed UDFs run on Modal.

Pixeltable Cloud builds the container image from your project's `uv.lock` and deploys the UDF servers when you run `pxt db update`. You only need a Pixeltable Cloud sign-in (`pxt login`), not a Modal account or token.

<Note>
  Only built-in synchronous UDFs under `pixeltable.functions` support `pixeltable.udf`. Custom `@pxt.udf` functions and async UDFs run in the local or hosted database process.
</Note>

## Configure UDF servers

Add one section per UDF under `[tool.pixeltable.udf]` in `pyproject.toml` (or `[pixeltable.udf]` in `pixeltable.toml`). Add a `[[tool.pixeltable.database]]` entry named `'local'` with `system_dependencies = ['ffmpeg']` when any offloaded UDF processes video or audio.

<Tabs>

### Resource fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `cpu` | `float` | `None` | vCPUs per container (must be greater than `0`). |
| `memory_mb` | `int` | `None` | Memory per container in MiB (must be greater than `0`). |
| `gpu` | `str` | `None` | Modal GPU specification, such as `'T4'`, `'L4'`, or `'H100:2'`. |
| `max_containers` | `int` | `2` | Maximum number of containers for that UDF server (must be greater than `0`). |
| `timeout_seconds` | `int` | `300` | Maximum seconds a call waits for its response, including queue time behind busy containers (`1` to `300`). |

Pixeltable sets `pixeltable.udf` at the project level only. Environment variables (`PIXELTABLE_UDF`) and `pxt.init()` overrides are ignored with a warning, and setting `pixeltable.udf` in `~/.pixeltable/config.toml` raises an error.

## Write the application file

Create `app.py` in the project directory. `Videos` runs FFmpeg operations on CPU containers, and `Frames` runs BLIP captioning, DETR object detection, bounding-box rendering, and CLIP indexing across Modal GPU and CPU containers.

```python
import pixeltable as pxt
from pixeltable.functions import huggingface, vision
from pixeltable.functions.video import concat_videos, frame_iterator
from pixeltable.serving import FastAPIRouter

TableModel = pxt.model_base()

CLIP_MODEL = 'openai/clip-vit-base-patch32'
CAPTION_MODEL = 'Salesforce/blip-image-captioning-base'
DETECTION_MODEL = 'facebook/detr-resnet-50'


class Videos(TableModel, name='videos'):
    video_id = pxt.Column(type=pxt.Int, primary_key=True)
    video: pxt.Video
    duration = video.get_duration()
    excerpt = video.clip(start_time=0.0, duration=2.0)
    segments = video.segment_video(duration=5.0)


class Frames(
    TableModel,
    name='frames',
    base=Videos,
    iterator=frame_iterator(video=Videos.video, fps=1),
):
    thumbnail = frame.resize((320, 180))
    rotated = frame.rotate(90)
    caption = huggingface.image_captioning(
        frame, model_id=CAPTION_MODEL, model_kwargs={'max_length': 30}
    )
    detections = huggingface.detr_for_object_detection(
        frame, model_id=DETECTION_MODEL, threshold=0.8
    )
    annotated = vision.bboxes_draw(
        frame, detections.boxes, labels=detections.label_text, width=3
    )
    __indexes__ = [
        pxt.EmbeddingIndex(
            frame,
            embedding=huggingface.clip.using(model_id=CLIP_MODEL),
            name='frame_ix',
        )
    ]


@pxt.query
def frames(video_id: int) -> pxt.Query:
    return (
        Frames.where(Frames.video_id == video_id)
        .order_by(Frames.pos)
        .select(
            Frames.pos,
            Frames.rotated,
            Frames.thumbnail,
            Frames.caption,
            Frames.detections,
            Frames.annotated,
        )
    )


@pxt.query
def similar_frames(text: str, limit: int = 3) -> pxt.Query:
    sim = Frames.frame.similarity(string=text)
    return (
        Frames.order_by(sim, asc=False)
        .limit(limit)
        .select(
            Frames.video_id,
            Frames.pos,
            Frames.caption,
            Frames.annotated,
            sim=sim,
        )
    )


@pxt.query
def with_excerpt(video_id: int) -> pxt.Query:
    return Videos.where(Videos.video_id == video_id).select(
        joined=concat_videos([Videos.video, Videos.excerpt])
    )


demo = FastAPIRouter(name='demo')
demo.add_insert_route(
    Videos,
    path='/videos',
    inputs=[Videos.video_id],
    uploadfile_inputs=['video'],
    outputs=[Videos.video_id, Videos.duration, Videos.excerpt, Videos.segments],
)
demo.add_query_route(path='/frames', query=frames)
demo.add_query_route(path='/similar', query=similar_frames)
demo.add_query_route(path='/with-excerpt', query=with_excerpt)
```

## Deploy and run

<Steps>
  <Step title="Install dependencies and lock the environment">
    Create the virtual environment and write `uv.lock`. Pixeltable Cloud uses `uv.lock` to build the container image for your UDF servers, and the local process also uses `torch` and `transformers` to encode text queries for `Frames.frame.similarity(string=...)`.

    ```bash
    uv sync
    source .venv/bin/activate
    ```
  </Step>
  <Step title="Sign in and deploy the UDF servers">
    Run `pxt login`, then run `pxt db update` without a database URI to build the image and deploy one Modal Server per `[tool.pixeltable.udf]` entry for your local database.

    ```bash
    pxt login
    pxt db update
    pxt db status
    ```

    The first `pxt db update` builds the container image (longer when `torch` and `transformers` are included) and prints progress until every server is ready. For a hosted database instead of a local database, pass its URI (`pxt db update pxt://org:db`).
  </Step>
  <Step title="Create the tables and start the HTTP service">
    `pxt schema update` creates `demo/videos` and `demo/frames`. `pxt service update` starts the local FastAPI service, and `pxt service list` prints its endpoint URL.

    ```bash
    pxt schema update app.py demo
    pxt service update app.py demo -f
    URL=$(pxt service list demo --json | jq -r '.[] | select(.name == "demo") | .endpoint')
    ```
  </Step>
  <Step title="Insert a video and query the service">
    Upload a video to `POST /videos`. The first insert spins up idle containers and caches Hugging Face weights on first inference; subsequent inserts reuse warm containers until they scale down after 60 seconds of inactivity.

    ```bash
    curl -F video_id=1 -F video=@sample.mp4 "$URL/videos"
    curl -H 'Content-Type: application/json' -d '{"video_id": 1}' "$URL/frames"
    curl -H 'Content-Type: application/json' -d '{"text": "busy street with traffic", "limit": 3}' "$URL/similar"
    curl -H 'Content-Type: application/json' -d '{"video_id": 1}' "$URL/with-excerpt"
    ```
  </Step>
</Steps>

## Update UDF settings and secrets

When you change `[tool.pixeltable.udf]`, edit project Python files, or update `uv.lock`, deploy the updated servers and restart the local service:

```bash
pxt db update
pxt service update app.py demo -f
```

Until `pxt db update` finishes, queries against the changed project fail with an error stating that the UDF servers run another version of the project.

If an offloaded UDF reads a provider key (such as `OPENAI_API_KEY` or `HF_TOKEN`), store it in Pixeltable Cloud with `pxt secret set` and redeploy with `pxt db update`:

```bash
pxt secret set pxt://org OPENAI_API_KEY=sk-...
pxt db update
```

Do not put secrets in `pixeltable.toml` or under `[tool.pixeltable]` in `pyproject.toml`. `pxt db update` rejects project configuration files that contain keys such as `api_key`, `api_secret`, `api_token`, `token`, `storage_account_key`, or `exporter_otlp_headers`. See [Configuration](/platform/configuration#per-database-settings).

## Inspect calls and clean up

With `log_level = "DEBUG"` in `pyproject.toml` or `pixeltable.toml`, Pixeltable logs one line per remote UDF call, including row count, round-trip time, in-container UDF execution time, and Modal container ID:

```bash
grep 'Modal call of' "${PIXELTABLE_HOME:-$HOME/.pixeltable}"/logs/*.log
```

Stop the local service, delete the deployed UDF servers (keeping your local tables and data intact), and stop the local daemon:

```bash
pxt service stop demo
pxt db delete
pxt daemon stop
```

Without `pxt db delete`, idle UDF servers run zero containers and incur no compute cost; Pixeltable Cloud deletes the UDF servers of a local database after 30 days without activity.
