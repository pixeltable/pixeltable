Create a hosted database. Apply the same [Quickstart](/overview/quick-start) file to a `pxt://` URI.

<Tip>
`PIXELTABLE_API_KEY` is required. Set it in the environment or in `config.toml`. See [Configuration](/platform/configuration).
</Tip>

```bash
pxt db create pxt://org:mydb
pxt secret set pxt://org OPENAI_API_KEY=sk-...
pxt schema update app.py pxt://org:mydb
```

Then `t = pxt.get_table('pxt://org:mydb/docs')`. `pxt schema update` creates the tables on the hosted catalog. It does not start HTTP.

<Warning>
`pxt service` binds to the **local** catalog. A `pxt://` target is refused. Browse and insert from the [dashboard](https://www.pixeltable.com); [recipes](https://www.pixeltable.com/recipes) run hosted insert APIs.
</Warning>

## Hosted catalog

Provider keys for hosted compute: `pxt secret set`, then `pxt db stop` / `pxt db start` or `pxt db update-runtime` so the running database picks them up.

Built-ins and provider functions in `app.py` apply on Cloud. A `@pxt.udf` or custom iterator defined only in a local file does not. Put it in the project packaged by `pxt db update-runtime`.

## Media on the home bucket

Every Cloud database includes a managed bucket. No provider account, no credentials file. Declare it on a computed column:

```python
class Images(TableModel, name='images'):
    photo: pxt.Image
    thumbnail = pxt.Column(
        value=photo.resize((256, 256)),
        destination='pxtfs://org:mydb/home',
    )
```

Or set `output_media_dest` as the default for computed media. Details: [Cloud storage](/integrations/cloud-storage).

## Local vs Cloud

| | Local | Cloud |
|---|---|---|
| Catalog | `pxt schema update app.py my_app` | `pxt schema update app.py pxt://org:mydb` |
| HTTP | `pxt service update app.py my_app` | Dashboard; `pxt service` is local-only |
| Media | local disk | `pxtfs://org:mydb/home` |

`pxt db` also lists, starts, stops, and deletes hosted databases, and `pxt db update-runtime` rebuilds the Python image. [CLI](/platform/cli#cloud).
