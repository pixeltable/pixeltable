Use the same `app.py` as the [Quickstart](/overview/quick-start). Sign in with `pxt login`, then create the hosted database, the tables, and hosted HTTP. You can use an API key instead of a login session.

## Sign in

`pxt login`, `pxt whoami`, and `pxt key` require Pixeltable 0.7.10 or later. Upgrade an existing installation with `pip install -U pixeltable`.

```bash
pxt login
pxt whoami
```

`pxt login` opens a browser and shows a code to confirm. If you have no organization yet, run `pxt org create org` and use that name in the `pxt://` commands below. Cloud is in Limited Beta; [contact us](mailto:contact@pixeltable.com) if you need access. An API key takes precedence over a login session when one is configured.

## Get an API key

For automation or hosted HTTP calls, create a key and export it. The CLI reads `PIXELTABLE_API_KEY` or `[pixeltable].api_key` from `~/.pixeltable/config.toml`. The environment variable takes precedence.

<Steps>
  <Step title="Sign in">
    New account: [pixeltable.com/signup](https://www.pixeltable.com/signup). Existing account: [pixeltable.com/login](https://www.pixeltable.com/login). After sign-in, the [dashboard](https://www.pixeltable.com/dashboard) opens your organization.
  </Step>
  <Step title="Create a key">
    Open **API Keys** in the organization sidebar, or go to `https://www.pixeltable.com/dashboard/your-org/api-keys`. Click **New**, or **Create API Key** if the list is empty. Name the key. Click **Create Key**. Copy the value now. The dashboard shows the full key once.
  </Step>
  <Step title="Export it">
    ```bash
    export PIXELTABLE_API_KEY='your-key'
    ```

    Or in `~/.pixeltable/config.toml`:

    ```toml
    [pixeltable]
    api_key = 'your-key'
    ```

    [Configuration](/platform/configuration). This key authenticates Cloud CLI and hosted HTTP. Provider keys such as `OPENAI_API_KEY` go under **Secrets** in the dashboard, or `pxt secret set pxt://org OPENAI_API_KEY=...`. They do not go in this API key. [CLI](/platform/cli#pxt-secret).
  </Step>
</Steps>

Run `pxt init` in your application directory:

```bash
pxt init
```

Add the hosted URL to the generated `pixeltable.toml`:

```toml
[[pixeltable.database]]
name = 'pxt://org:mydb'
```

```bash
pxt db update pxt://org:mydb
pxt schema update app.py pxt://org:mydb
pxt service update app.py pxt://org:mydb
```

A Cloud table path uses the URI plus `/table`. Open it with `t = pxt.get_table('pxt://org:mydb/docs')`. A local table uses dotted `namespace.table`, such as `pxt.get_table('my_app.docs')`.

```python
import pixeltable as pxt
import pixeltable.functions as pxtf
from pixeltable.serving import FastAPIRouter

TableModel = pxt.model_base()


class Docs(TableModel, name='docs'):
    title: pxt.String
    body: pxt.String | None
    title_upper = pxtf.string.upper(title)


ingest = FastAPIRouter(name='ingest')
ingest.add_insert_route(
    Docs, path='/docs', inputs=[Docs.title, Docs.body], outputs=[Docs.title, Docs.title_upper]
)
```

The same file can hold `pxt.Image`, `pxt.Video`, `pxt.Audio`, or `pxt.Document`: [media pipelines](/use-cases/media-processing), [RAG](/use-cases/multimodal-backend).

`pxt db update` creates the hosted database or updates its image, project files, and size. Set provider secrets with `pxt secret set`. `pxt db update` does not insert data or start app endpoints. `pxt schema update` creates the tables. `pxt service update` starts hosted endpoints. `pxt service run` starts endpoints in your local terminal.

After the database is up, insert from the Cloud dashboard or from Python. A local file path on a Cloud table uploads the file. Run `pxt schema diff app.py pxt://org:mydb` to see pending schema changes.

Use `pxt service list pxt://org:mydb` to find the hosted service URL. Call its route with an API key in `X-api-key`; `pxt key create NAME` prints a key once. Use `pxt db logs pxt://org:mydb` and `pxt service logs pxt://org:mydb/ingest` to inspect running services.

After `pxt secret set pxt://org:mydb KEY=VALUE`, run `pxt db restart pxt://org:mydb` for table processes and `pxt service restart pxt://org:mydb/ingest` for the service. Running processes read secrets when they start.

## Media on the home bucket

Every Cloud database includes a managed Media Store at `pxtfs://org:mydb/home`. Hosted tables and services use it by default, so no `destination=` setting is needed. Set `destination=` only when a computed column should write elsewhere:

```python
class Images(TableModel, name='images'):
    photo: pxt.Image
    thumbnail = pxt.Column(
        value=photo.resize((256, 256)),
        destination='s3://my-bucket/thumbnails',
    )
```

Or set `output_media_dest` as the default for computed media. Details: [Cloud storage](/integrations/cloud-storage#pixeltable-cloud-home-bucket).

## Local vs Cloud

| | Local | Cloud |
|---|---|---|
| Hosted database | not needed | `pxt db update pxt://org:mydb` |
| Tables | `pxt schema update app.py my_app` | `pxt schema update app.py pxt://org:mydb` |
| HTTP | `pxt service update app.py my_app` | `pxt service update app.py pxt://org:mydb` |
| Try a change | insert, `pxt dashboard`, `pxt schema diff app.py my_app` | dashboard insert, `pxt schema diff app.py pxt://org:mydb` |
| Media | local disk | `pxtfs://org:mydb/home` |

`pxt db` also lists, starts, stops, diffs, and deletes hosted databases. `pxt db build-image` rebuilds the Python image without waiting for drift. [CLI](/platform/cli#cloud).
