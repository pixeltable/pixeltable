Python 3.11+ on Linux, macOS, or Windows. Tables, computed columns, and HTTP routes live in one file. Insert runs compute.

## Install

<Tabs>
  <Tab title="venv">
    ```bash
    python -m venv .venv
    source .venv/bin/activate   # Windows: .venv\Scripts\activate
    pip install 'pixeltable[serve]'
    ```
  </Tab>
  <Tab title="uv">
    ```bash
    uv venv --python 3.12
    source .venv/bin/activate   # Windows: .venv\Scripts\activate
    uv pip install 'pixeltable[serve]'
    ```
  </Tab>
</Tabs>

`[serve]` pulls in FastAPI and uvicorn, which `pxt service` needs. No HTTP: `pip install pixeltable` is enough.

## Declare, apply, serve

<Steps>
  <Step title="Write the file">
    `pxt service example` writes a working application file — models and a `FastAPIRouter` in one place.

    ```bash
    pxt service example --out app.py
    ```

    The shape is this (`from __future__ import annotations` is required on Python 3.14+). The command adds a UDF and a compute route; delete what you do not need.

    ```python
    from __future__ import annotations  # required to declare a model on Python 3.14+

    import pixeltable as pxt
    import pixeltable.functions as pxtf
    from pixeltable.serving import FastAPIRouter

    TableModel = pxt.model_base()


    class Docs(TableModel, name='docs'):
        title: pxt.String                         # a stored column
        body: pxt.String | None                   # a stored column that may be null
        title_upper = pxtf.string.upper(title)    # a computed column: an assignment, not an annotation


    ingest = FastAPIRouter(name='ingest')
    ingest.add_insert_route(
        Docs, path='/docs', inputs=[Docs.title, Docs.body], outputs=[Docs.title, Docs.title_upper]
    )
    ```

    An annotation is a stored column. An assignment is a computed column.
  </Step>
  <Step title="Apply, then serve">
    ```bash
    pxt schema update app.py my_app
    pxt service update app.py my_app
    ```

    `my_app` is a catalog directory, not a folder next to `app.py`. `pxt schema update` creates that directory and the tables. It does not start HTTP. `pxt service update` does not create tables. Apply first.
  </Step>
  <Step title="Insert a row">
    `title_upper` is computed on the way in. `pxt service list` prints the URL (the port is assigned):

    ```bash
    pxt service list
    # ingest  http://127.0.0.1:<port>  ...
    curl -X POST http://127.0.0.1:<port>/docs \
      -H 'Content-Type: application/json' \
      -d '{"title": "Hello", "body": "world"}'
    ```
  </Step>
</Steps>

## The CLI

`pxt` ships with the package. The first catalog command starts a local daemon (`127.0.0.1:22089`). It stays up across shells. `pxt health` confirms it.

| Command | What it does |
|---|---|
| `pxt service example --out app.py` | Write a working file: models plus routes |
| `pxt schema example --out schema.py` | Schema only. `--brief` is the minimal models; without it, every DSL construct |
| `pxt schema update FILE TARGET` | Create and migrate the tables `FILE` declares under `TARGET` |
| `pxt service update FILE TARGET` | Start the services `FILE` declares against those tables |
| `pxt service list` | What is running, and the URL |
| `pxt ls my_app` | Tables under the catalog directory |
| `pxt rows my_app/docs` | Peek stored cells |
| `pxt dashboard` | Local UI on the daemon |

`diff` / `update` / `prune` are the same verbs on both `pxt schema` and `pxt service`. Full flags: [CLI](/platform/cli).

Tables live under `~/.pixeltable` (`pgdata`, `media`, `file_cache`). That path is not the project directory. Project layout and `pixeltable.toml`: [Infrastructure](/howto/deployment/infrastructure).

## Same file, other first runs

<Tabs>
  <Tab title="No HTTP">
    Skip `[serve]`. `pxt schema example --brief` writes models only.

    ```bash
    pip install pixeltable
    pxt schema example --brief --out app.py
    pxt schema update app.py my_app
    ```

    Then insert from Python (`t = pxt.get_table('my_app.docs')`) or export and exit. [Self-hosting](/howto/deployment/overview).
  </Tab>
  <Tab title="Cloud">
    Same file against a hosted catalog. `PIXELTABLE_API_KEY` is required. `pxt service` stays local.

    ```bash
    pxt db create pxt://org:mydb
    pxt schema update app.py pxt://org:mydb
    ```

    [Deploy to Pixeltable Cloud](/howto/deployment/cloud).
  </Tab>
  <Tab title="Starter kit">
    [`uvx pixeltable-new`](https://github.com/pixeltable/pixeltable-new) copies a full app. Default is the chat agent (TARGET `agent`). `--video` is video search (`videointel`).

    ```bash
    uvx pixeltable-new myapp
    cd myapp
    uv sync
    pxt schema update app.py agent
    pxt service update app.py agent
    ```

    [Starter kit](/resources/starter-kit).
  </Tab>
</Tabs>

<Note>
**App vs notebook.** An application's contract is a `TableModel` in `app.py`, applied with `pxt schema update`. Notebooks and tests use `pxt.create_table()`, `add_computed_column()`, and `add_embedding_index()`.
</Note>
