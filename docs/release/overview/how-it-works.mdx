[Quickstart](/overview/quick-start) is the first run. This page is the model those commands sit on.

One Python file declares tables and, if you want HTTP, routes. `pxt schema` creates the tables. `pxt service` starts a process on a port. The target on the command line is a **catalog directory** (`my_app`) or a hosted URI (`pxt://org:db`). It is not a folder next to `app.py`.

On disk you keep `app.py` (and, for a project, `pixeltable.toml`). In the catalog you get `my_app/docs`. Inspect with `pxt ls my_app`. Layout: [Infrastructure](/howto/deployment/infrastructure).

Schema and services use the same verbs:

| Verb | What it does |
|---|---|
| `diff` | What `update` would change. Exit `0` in sync, `2` pending, `1` error |
| `update` | Make the instance match the file. No-op if it already does |
| `prune` | Remove instance parts the file does not declare |
| `example` | Write a working file to start from |

Full flags: [CLI](/platform/cli).

## Schema

An annotation (`title: pxt.String`) is a stored column — you insert that value. An assignment (`title_upper = ...`) is a computed column. It runs on insert and on update. Use `pxt.Column(...)` when you need a primary key, `stored=False`, or a media option an annotation cannot express.

A model with `base=` is a view. `base=Docs.where(...)` inherits columns and filters. `base=Docs` plus an iterator is a component view (one row per chunk, frame, sentence). Indexes belong on the model (`__indexes__` or an `EmbeddingIndex` assignment), not `add_embedding_index()` after apply.

`pxt schema example` writes every construct. `--brief` is the minimal models. Apply with `pxt schema update app.py my_app`. Tables under `TARGET` that no model declares are left alone; `pxt schema prune` drops them.

A `@pxt.udf` defined in the file is recorded by file path. Renaming the file leaves columns that call it unable to compute.

## Services

The same file declares a `FastAPIRouter`. `pxt service update` starts it against tables that already exist. Apply schema first. `pxt service list` prints the URL; the port is assigned. Do not hard-code `:8000`.

Insert stores a row and returns `outputs`. Compute runs the same columns and writes nothing. Update and delete match a row (primary key by default). Uploads, background jobs, query routes, and `include_router`: [HTTP serving](/howto/deployment/serving).

A schema change with a service already running needs `pxt service update` after `pxt schema update`. Route-only edits: `pxt service update` restarts what changed. Inspect with `pxt dashboard`, `pxt ls`, and `pxt errors`.

## Database

<Tabs>
  <Tab title="Local">
    No account. [Quickstart](/overview/quick-start) applies the file on this machine. Local HTTP: [Self-hosting](/howto/deployment/overview).

    ```bash
    pxt schema update app.py my_app
    pxt service update app.py my_app
    ```
  </Tab>
  <Tab title="Cloud">
    Same file, a `pxt://` target. [Deploy to Pixeltable Cloud](/howto/deployment/cloud). `pxt service` stays local.

    ```bash
    pxt db create pxt://org:mydb
    pxt schema update app.py pxt://org:mydb
    ```
  </Tab>
</Tabs>
