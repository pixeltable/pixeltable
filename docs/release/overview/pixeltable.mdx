Pixeltable is the unified multimodal backend for AI data apps: the database, orchestration, and serving layers in **one application file** (`app.py`). You process media, run models, and serve the result without assembling a blob store, a vector database, an orchestrator, and glue.

Insert a row. Computed columns run. Indexes stay current.

<Columns cols={3}>
  <Card title="Store" icon="database">
    `pxt schema update` creates the tables `app.py` declares. Images, video, audio, documents, and structured columns live in one catalog.
  </Card>
  <Card title="Transform" icon="bolt">
    Assigned columns run on insert. Embedding indexes update. No extra queue or cache to keep in sync.
  </Card>
  <Card title="Serve" icon="globe">
    `pxt service update` starts HTTP from the same file. `pxt service list` prints the URL.
  </Card>
</Columns>

```python
import pixeltable as pxt
import pixeltable.functions as pxtf
from pixeltable.serving import FastAPIRouter

TableModel = pxt.model_base()


class Docs(TableModel, name='docs'):
    title: pxt.String
    body: pxt.String | None
    title_upper = pxtf.string.upper(title)


ingest = FastAPIRouter(name='ingest')
ingest.add_insert_route(
    Docs,
    path='/docs',
    inputs=[Docs.title, Docs.body],
    outputs=[Docs.title, Docs.title_upper],
)
```

[Quickstart](/overview/quick-start) is the first run. Schema, database, and services: [How it works](/overview/how-it-works). Same file on a hosted catalog: [Cloud](/howto/deployment/cloud).

RAG, media, agents, and HTTP are columns and views in that file. They update when the row does. Stack-shaped snippets: [Coming from...](/howto/coming-from).

**Apps vs notebooks.** To ship an app, put tables in a Python file and apply it. In a notebook or a test you can create tables as you go. Same catalog either way; the file is what you keep.
