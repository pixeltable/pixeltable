Pixeltable is the unified multimodal backend for AI data apps in **one application file** (`app.py`). You process media, run models, and serve the result without assembling a blob store, a vector database, an orchestrator, and glue.

Insert a row. Computed columns run. Indexes stay current.

```python
import pixeltable as pxt
import pixeltable.functions as pxtf
from pixeltable.serving import FastAPIRouter

TableModel = pxt.model_base()


class Docs(TableModel, name='docs'):
    title: pxt.String
    body: pxt.String | None
    title_upper = pxtf.string.upper(title)


ingest = FastAPIRouter(name='ingest')
ingest.add_insert_route(
    Docs,
    path='/docs',
    inputs=[Docs.title, Docs.body],
    outputs=[Docs.title, Docs.title_upper],
)
```

An annotation (`title`) is a stored column. An assignment (`title_upper`) is computed on insert.

<Steps>
  <Step title="Apply">
    ```bash
    pxt schema update app.py my_app
    ```

    Creates the tables. It does not start HTTP.
  </Step>
  <Step title="Insert">
    ```python
    t = pxt.get_table('my_app.docs')
    t.insert([{'title': 'Hello', 'body': 'world'}])
    ```

    `title_upper` is computed. Indexes stay current.
  </Step>
  <Step title="Serve">
    ```bash
    pxt service update app.py my_app
    pxt service list
    ```

    Starts HTTP from the same file. The port is assigned.
  </Step>
</Steps>

First run: [Quickstart](/overview/quick-start). `diff` / `update` / `prune`: [How it works](/overview/how-it-works). Same file on a hosted catalog: [Cloud](/howto/deployment/cloud).

Pinecone, Postgres, and LangGraph map onto columns in that file. [Migrate](/howto/coming-from).

**Apps vs notebooks.** To ship an app, put tables in a Python file and apply it. In a notebook or a test you can create tables as you go. Same catalog either way; the file is what you keep.
