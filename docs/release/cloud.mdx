The [Quickstart](/overview/quick-start) runs `app.py` locally. Here, the same application file creates tables and starts HTTP on a hosted database. A `pxt login` session is enough for the first deployment; you do not need an API key.

## First deployment

<Steps>
  <Step title="Install Pixeltable and sign in">
    `pxt login`, `pxt whoami`, and `pxt key` require Pixeltable 0.7.10 or later.

    ```bash
    pip install -U 'pixeltable[serve]'
    pxt login
    pxt whoami
    pxt org list
    ```

    `pxt login` shows a code to confirm in your browser. Use the organization name from `pxt org list` in the `pxt://` commands below. If you have no organization, run `pxt org create org` first.
  </Step>
  <Step title="Prepare the application and Cloud target">
    In a new directory, run:

    ```bash
    mkdir cloud-app && cd cloud-app
    pxt init
    pxt service example --out app.py
    ```

    `pxt service example` writes a working `app.py` with a `Docs` table and an `ingest` HTTP service. If you already completed the Quickstart, use that `app.py` instead.

    Add a hosted database entry to the `pixeltable.toml` that `pxt init` created. Replace `org` with your organization name:

    ```toml
    [[pixeltable.database]]
    name = 'pxt://org:mydb'
    ```

    Keep the local database entry that `pxt init` wrote. If your project has a `pyproject.toml`, `pxt init` adds its entry there instead; use `[[tool.pixeltable.database]]` for the hosted entry.
  </Step>
  <Step title="Create the database, tables, and service">
    Run these commands from the project directory, in order:

    ```bash
    pxt db update pxt://org:mydb
    pxt schema update app.py pxt://org:mydb
    pxt service update app.py pxt://org:mydb
    pxt service list pxt://org:mydb
    ```

    `pxt db update` creates the hosted database and uploads the project. `pxt schema update` creates its tables. `pxt service update` starts the HTTP service. `pxt service list` prints its URL and routes.
  </Step>
  <Step title="Insert a row and check the result">
    The generated `app.py` defines a `docs` table with a computed `title_upper` column. Insert a row from Python:

    ```python
    import pixeltable as pxt

    docs = pxt.get_table('pxt://org:mydb/docs')
    docs.insert(title='Hello', body='world')
    print(docs.select(docs.title, docs.title_upper).collect())
    ```

    The result includes `Hello` and `HELLO`. The insert computes `title_upper` on Cloud. You can also insert and inspect rows in the signed-in [Cloud dashboard](https://www.pixeltable.com/dashboard).
  </Step>
</Steps>

## Get an API key

API keys are optional for the CLI and Python workflow above. Create one for CI, background jobs, or a backend that calls a hosted HTTP service. If a browser frontend needs that service, have it call your backend. Keep the key out of browser code.

After `pxt login`, create a key from the CLI:

```bash
pxt key create my-app
```

The CLI prints the secret once. `pxt key list` shows key names, but cannot show their secrets again. A key created without `--grant` acts as you. [Scoped service keys](/platform/cli#pxt-key) are in preview. You can also create a key under **API Keys** in the [Cloud dashboard](https://www.pixeltable.com/dashboard).

### Call the hosted service

Get the service URL from `pxt service list pxt://org:mydb`. Put the key in your backend's environment and send it in the `X-api-key` header:

```bash
export PIXELTABLE_API_KEY='your-key'
SERVICE_URL='URL from pxt service list'
curl -X POST "$SERVICE_URL/docs" \
  -H "X-api-key: $PIXELTABLE_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"title": "Hello from HTTP", "body": "world"}'
```

For CLI automation or Python clients, `PIXELTABLE_API_KEY` also works as a credential. A configured key takes precedence over a `pxt login` session. [Configuration](/platform/configuration) lists the available settings.

### Call from Next.js on Vercel

Set `PIXELTABLE_SERVICE_URL` to the full URL from `pxt service list` and `PIXELTABLE_API_KEY` to your key in your Next.js server environment. Set both in Vercel's project environment variables when you deploy. Do not prefix the key with `NEXT_PUBLIC_`.

Follow [Call from a TypeScript app server](/howto/deployment/serving#call-from-a-typescript-app-server) to generate `src/pixeltable.d.ts` from the hosted service and create `src/lib/pixeltable-client.ts`. That client sends the key and exports `computeTitle()` for the generated app's `/titles` route. Then add a Route Handler at `src/app/api/title/route.ts`:

```typescript
import { computeTitle } from '@/lib/pixeltable-client';

export async function POST(request: Request) {
  const { title } = await request.json();
  if (typeof title !== 'string' || !title.trim()) {
    return Response.json({ error: 'Enter a title' }, { status: 400 });
  }

  const result = await computeTitle(title);
  if (!result) {
    return Response.json({ error: 'Empty service response' }, { status: 502 });
  }
  return Response.json({ title_upper: result.title_upper });
}
```

Call that handler from a client component, such as `src/app/page.tsx`:

```tsx
'use client';

import { useState, type FormEvent } from 'react';

export default function Page() {
  const [title, setTitle] = useState('');
  const [result, setResult] = useState('');

  async function submit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const response = await fetch('/api/title', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ title }),
    });
    if (!response.ok) {
      setResult('Request failed');
      return;
    }
    const body: { title_upper: string } = await response.json();
    setResult(body.title_upper);
  }

  return (
    <form onSubmit={submit}>
      <input value={title} onChange={(event) => setTitle(event.target.value)} />
      <button type="submit">Uppercase title</button>
      <p>{result}</p>
    </form>
  );
}
```

The browser calls `/api/title`; the Route Handler calls Pixeltable. Add your application's authorization checks to the handler before exposing costly or data-changing routes to users. Regenerate the types when you change routes in `app.py`.

## Add provider secrets

`PIXELTABLE_API_KEY` authenticates to Pixeltable Cloud. Provider keys, such as `OPENAI_API_KEY`, belong in Cloud **Secrets**. For a database that uses OpenAI:

```bash
pxt secret set pxt://org:mydb OPENAI_API_KEY=your-provider-key
pxt db restart pxt://org:mydb
pxt service restart pxt://org:mydb/ingest
```

The restarts let running table and service processes read the new value. You can also set secrets in the [Cloud dashboard](https://www.pixeltable.com/dashboard). [CLI secret commands](/platform/cli#pxt-secret).

## Update and inspect the deployment

After editing `app.py` or dependencies, run `pxt db update pxt://org:mydb` to update the hosted project or image. If you changed tables, follow it with `pxt schema update app.py pxt://org:mydb`. If you changed HTTP routes, follow it with `pxt service update app.py pxt://org:mydb`. Use the corresponding `diff` commands to see pending changes first. [CLI reference](/platform/cli#cloud).

```bash
pxt db logs pxt://org:mydb
pxt service logs pxt://org:mydb/ingest
```

These commands show database and service logs when a deployment or request fails.

## Media on the home bucket

A Cloud database has a managed Media Store at `pxtfs://org:mydb/home`. Hosted tables and services use it by default; normal media columns need no `destination=` setting. To write computed media to your own bucket, set `destination=` on that column or configure `output_media_dest`. [Cloud storage](/integrations/cloud-storage#pixeltable-cloud-home-bucket).
